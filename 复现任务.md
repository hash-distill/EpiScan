## 三、任务二：Custom 数据集实验

### 3.1 输入数据格式

`dataProcess/custom/fasta_label4.5.tsv` — 6 列 TSV，4742 行（含表头）：


| 列             | 含义              | 示例              |
| -------------- | ----------------- | ----------------- |
| antigen_id     | 抗原 ID           | `1A14_N`          |
| antigen_seq    | 抗原序列          | `RIDPVAMTHT...`   |
| antigen_label  | 表位标签 (0/1 串) | `000...111...000` |
| antibody_id    | 抗体 ID           | `1A14_H`          |
| antibody_seq   | 抗体序列          | `QVQLQQSGAE...`   |
| antibody_label | 抗体 CDR 标签     | `000...111...000` |

训练/测试划分：`epitope_ratio_train_pdb_ids4645.txt`（1368 对）和 `epitope_ratio_test_pdb_ids4645.txt`（156 对）。

### 3.2 与 DB1 的差异

Custom 数据是 6 列含序列格式，而训练脚本需要 4 列 TSV（仅 ID）+ 单独的 pickle 特征 + H5 嵌入。需将：


| 原始信息                 | → | 目标格式                               | 处理方法                                             |
| ------------------------ | -- | -------------------------------------- | ---------------------------------------------------- |
| xyx_abag.zip (PDB)       | → | `custom_pdb_dict_AgAb.pickle`          | 从 PDB 提取 3D坐标 + SASA + 局部频率 → 66维抗原特征 |
| 所有序列 (抗原+抗体)     | → | `custom_all_proteins.h5`               | `embed.py` 生成全部蛋白的语言模型嵌入（**必须含抗原**）|
| 抗体序列 + PDB           | → | `custom_cdr_dict.pickle`               | ANARCI Kabat 编号标注 CDR 位置                       |
| 抗体序列 + PDB           | → | `custom_catsite_dict.pickle`           | ANARCI 推断 VH/VL 切割位点                           |
| 以上汇总 + antigen_label | → | `custom_train.tsv` / `custom_test.tsv` | 4 列 TSV                                             |

> ⚠️ **关键**：训练脚本会从 H5 加载**所有**蛋白（抗原+抗体）。`custom_all_proteins.h5` 必须包含全部 9482 条蛋白，不能用只含抗体的 `custom_antibodies.h5`，否则报 `KeyError`。

### 3.3 数据依赖关系

```
xyx_abag.zip (4742 PDB)
  ├── 抗原链 → 3D坐标[0:3] + FreeSASA SASA[64:66] + 8Å频率谱[44:64] + one-hot[3:23]
  │              → custom_pdb_dict_AgAb.pickle (66维)
  ├── 抗体链 → ANARCI → CDR位置 → custom_cdr_dict.pickle
  └── 抗体链 → ANARCI → VH长度 → custom_catsite_dict.pickle

fasta_label4.5.tsv
  ├── 全部序列 → 生成 custom_all_proteins.fasta → embed.py → custom_all_proteins.h5
  ├── antigen_label → TSV 第3列
  ├── antigen_id + antibody_id → TSV 第1-2列
  └── catsite_dict → TSV 第4列
```

### 6.2 各步骤与所用脚本


| 步骤                | 脚本                         | 输入                          | 输出                                        | 耗时    |
| ------------------- | ---------------------------- | ----------------------------- | ------------------------------------------- | ------- |
| 1. 解压 PDB         | `unzip`                      | `xyx_abag.zip`                | `pdb/` 目录                                 | 5 min   |
| 2. 提取全部蛋白 FASTA | 单行 Python                | `fasta_label4.5.tsv`          | `custom_all_proteins.fasta` (9482 条)       | 1 min   |
| 3. 生成 H5 嵌入     | `embed.py`                   | `custom_all_proteins.fasta`   | `custom_all_proteins.h5` (30 GB) ⭐         | ~35 min |
| 4. PDB→Pickle 特征 | `build_features_from_pdb.py` | PDB + TSV                     | 3 个 pickle 文件                            | ~40 min |
| 5. 生成 TSV         | `generate_tsv.py`            | pickle + TSV + ID 列表        | `custom_train.tsv` + `custom_test.tsv`      | 1 min   |
| 6. 生成 5 折划分    | `generate_custom_5fold.py`   | TSV + ID 列表                 | `custom_fold{0-4}_{train,val}.tsv`          | 1 min   |

> ⚠️ **嵌入文件必须用 `custom_all_proteins.h5`**：训练脚本会从 H5 加载所有蛋白（抗原+抗体）。只用抗体的 `custom_antibodies.h5` 会在加载抗原时抛 `KeyError`。

### 6.3 核心脚本说明

**`scripts/build_features_from_pdb.py`**（核心，~300 行）

遍历 4742 个 PDB 文件，对每个结构：

1. 解析 CA 原子坐标 → 抗原 66 维特征的 `[0:3]`（3D 坐标）
2. FreeSASA 计算溶剂可及表面积 → `[64:66]`
3. 计算 8Å 半径内氨基酸频率 → `[44:64]`
4. 序列 one-hot 编码 → `[3:23]`，PSSM 零填充 `[23:44]`
5. 对每条抗体链，用 ANARCI 做 Kabat 编号 → CDR 位置 + VH 长度（catsite）

运行命令：

```bash
conda run -n episcan python scripts/build_features_from_pdb.py 2>&1 | tee ./output/build_features.log
```

**`scripts/generate_tsv.py`**

将 catsite 字典与原始 TSV 合并，输出 4 列格式的训练/测试 TSV。

### 6.4 维度修复记录

首次生成的抗原特征为 65 维（PSSM 只给了 20 列，少 1 列 bias），已通过补齐脚本修复为 66 维。最终校验：

- 抗原(66维): 4741 个，抗体(46维): 4741 个

- 训练集 1368 对、测试集 156 对，全部 ID 在 pickle 中可查

### 7.3 代码修改记录

**`train_sep-auc.py`**（✅ 已修改，为跑通 custom 数据做了以下修复）：

| 修改 | 原因 |
|------|------|
| 新增 `--pdb-dict` / `--cdr-dict` / `--out-metrics` 参数 | 指定自定义 pickle 路径、保存指标 CSV |
| 硬编码 pickle 路径替换为参数引用 | 无需符号链接 |
| **移除 libauc `CompositionalAUCLoss`** | 与当前 PyTorch 版本不兼容，触发 CUDA assert |
| **`torch.clamp(ph, 1e-7, 1-1e-7)` 保护所有 loss 输入** | 防止模型输出越界触发 CUDA assert |
| **`interaction_eval` 用 `torch.cat` 拼接标签**（原 `torch.stack`）| 最后一个 batch 尺寸不足时 `stack` 报错 |
| **CDR 索引按实际嵌入长度过滤** | PDB 派生 CDR 字典与 TSV 嵌入长度可能不一致 |
| **抗原特征长度对齐（pad/截断）** | 6 个蛋白 PDB 链比 TSV 序列短 1-3 残基 |
| **只保存最优模型**（AUC 提升时覆盖 `best_final.sav`）| 避免每个 epoch 存 500+ 文件 |
| 训练过程/指标输出到终端 | 便于监控 |

**`models/contact_sep.py`**（✅ 已修改）：

| 修改 | 原因 |
|------|------|
| CDR 索引 off-by-one：`<=` → `<` | 允许索引 = N 导致 `torch.gather` 越界 |
| 索引张量 `device=z1H.device`（原硬编码 `.cuda()`）| 设备不匹配错误 |
| **空索引列表填占位符 `[0]`** | CDR 全在单侧时 gather 空维 → mean → NaN |
| 索引 `clamp` 到有效范围 | 防止越界 |

**`epimapping.py`**（✅ 已修改）：

- 新增 `--pdb-dict`、`--cdr-dict`、`--checkpoint` 参数
- 替换所有硬编码路径
- 支持加载完整模型或 state_dict

> 全部修复已通过验证：1368 个训练样本 GPU 前向传播零失败，1 epoch 训练 + 评估完整跑通（AUC≈0.60）。

## 九、常见问题与排查


| 问题                                   | 原因              | 解决                                                             |
| -------------------------------------- | ----------------- | ---------------------------------------------------------------- |
